Harness SDK ships as one npm package with explicit subpath exports for providers and testing.

## Requirements

- Node.js 22.13 or newer
- A stable, application-owned directory for Harness data
- An installed local provider or a reachable Mastra agent for real turns

<Steps>
  <Step title="Install the package">

```bash
npm install @triadlabs/harness-sdk
```

  </Step>
  <Step title="Prepare a provider">

For Codex, install and authenticate the Codex CLI so `codex app-server` can start. For Claude, authenticate Claude Code with `claude auth login` or provide credentials through the process environment.

For Mastra, also install its optional client and configure the agent endpoint:

```bash
npm install @mastra/client-js
```

  </Step>
  <Step title="Choose a data directory">

Pass a stable `homeDir` when you create Harness. The production default stores data at `homeDir/harness.sqlite3` and operational logs under `homeDir/logs`.

  </Step>
</Steps>

## Package entrypoints

| Import                                  | Purpose                                                           |
| --------------------------------------- | ----------------------------------------------------------------- |
| `@triadlabs/harness-sdk`                | Core orchestration, storage, events, lifecycle, and adapter types |
| `@triadlabs/harness-sdk/codex`          | Codex app-server adapter                                          |
| `@triadlabs/harness-sdk/claude`         | Claude Agent SDK adapter                                          |
| `@triadlabs/harness-sdk/mastra`         | Mastra-native remote agent adapter                                |
| `@triadlabs/harness-sdk/testkit`        | Deterministic fake provider without a test-runner dependency      |
| `@triadlabs/harness-sdk/testkit/vitest` | Optional Vitest provider and storage contract suites              |

The subpaths are not separate npm packages. The Mastra subpath has one optional peer dependency, `@mastra/client-js`, which is only needed by applications that import it.

## Check provider status

Harness reports provider availability but never installs or logs in to an agent for you.

```ts
const status = await harness.providers.codex.status();

switch (status.state) {
  case "ready":
    console.log("Codex is ready", status.version);
    break;
  case "not_installed":
  case "not_authenticated":
  case "unavailable":
    console.error(status.message);
    break;
}
```

<Warning>
  Do not use `createMemoryStore()` for production persistence. It is intended for deterministic
  tests and deliberately ephemeral programs.
</Warning>
