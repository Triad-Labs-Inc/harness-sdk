Use this prompt with Codex, Claude Code, Cursor, or another coding agent. It starts from the tested [Harness Electron Starter](https://github.com/Triad-Labs-Inc/harness-electron-starter) instead of rebuilding the Electron and Harness boundary from scratch.

<Tip>
  Start the coding agent in an empty directory to clone the starter there. If the directory already
  contains files, the prompt requires the agent to create a separate `harness-electron-app`
  directory without touching the existing project.
</Tip>

## Copy the prompt

```text
Create my Electron coding-agent application from the official Harness Electron Starter:

https://github.com/Triad-Labs-Inc/harness-electron-starter

Do not rebuild the application from scratch. Clone the tested starter, establish a passing baseline, and then customize it without weakening its Harness or Electron security boundaries.

Before writing files:

1. Inspect the current directory.
2. If it is completely empty, clone the starter into the current directory:
   git clone https://github.com/Triad-Labs-Inc/harness-electron-starter.git .
3. If the current directory contains `.git` or any other files, create a child directory named `harness-electron-app` and clone the starter there. If that name exists, use the next available name such as `harness-electron-app-2`.
4. Work only inside the cloned starter. Never delete, overwrite, or reconfigure unrelated files.
5. Rename the cloned `origin` remote to `upstream` so later work cannot accidentally push to the official starter:
   git remote rename origin upstream

Read the complete README and inspect `package.json`, `src/main`, `src/preload`, `src/shared`, and `src/renderer` before changing code.

Establish the baseline first:

- Use Node.js 22.13 or newer.
- Run `npm ci`.
- Run `npm run check`, `npm run build`, and `npm run smoke`.
- The baseline must not require Codex, Claude, network access after installation, credentials, login, or paid usage.
- If a baseline command fails, diagnose it before making product changes and report the exact failure.

Preserve these non-negotiable boundaries while customizing:

- Continue using the published `@triadlabs/harness-sdk` package and only its public entrypoints.
- Harness, provider adapters, SQLite, subscriptions, and provider processes must stay in Electron's main process.
- Keep the renderer sandboxed with `contextIsolation` enabled and `nodeIntegration` disabled.
- Add renderer capabilities only through narrow typed preload methods and validated IPC handlers.
- Never persist, log, or send credentials or complete environment values to the renderer.
- Keep raw provider-event persistence at `none` unless I explicitly request and justify a different policy.
- Do not expose arbitrary shell or process-spawning APIs to the renderer.
- Do not install providers, perform login, or automatically discover adapters.

Preserve the starter's working session behavior:

- Multiple independent Codex and Claude sessions remain navigable from the session list.
- One turn is active per session; additional `send()` calls queue.
- Steering and interruption remain explicit user actions.
- Permissions and agent questions remain separate interactions.
- Snapshot loading and subscription continue without an event gap.
- Slow subscribers replay from `SlowConsumerError.lastSequence`.
- Active turns surface `HOST_RESTARTED` after a host crash, and queued work resumes only after an explicit user action.
- Accepted turns are never automatically replayed after a provider crash.
- App shutdown closes subscriptions and Harness gracefully.

Customize the starter for this product request:

[DESCRIBE THE APP, BRAND, AND FEATURES YOU WANT HERE]

If the request does not specify branding, keep the starter's neutral Harness Workbench identity. If it does, update the application name, package metadata, window title, first-run copy, and CSS design tokens consistently. Keep the interface focused on sessions and agent work; do not add an arbitrary terminal, hosted service, account system, auto-update, installer, worktree support, or automatic provider login unless I explicitly request it.

Add or update deterministic tests for every behavior you change. Real Codex and Claude checks must remain optional. Before stopping, run:

- `npm run check`
- `npm run build`
- `npm run smoke`
- `npm audit --audit-level=high`

Then launch the production app with `npm start` and verify the first-run screen, new-session dialog, session navigation, and composer in the real Electron window.

When finished, tell me:

- Which directory you used.
- What you changed and where the main extension points are.
- Every verification command you ran and whether it passed.
- How to launch the app.
- Any optional real-provider step I still need to perform manually.

Do not stop at scaffolding. Continue until the customized app builds, its offline suite passes, and the Electron interface launches, unless a genuine external blocker prevents it.
```

The repository is also a GitHub template, so you can select **Use this template** when you want GitHub to create a clean repository for your application. Review the [Electron guide](/guides/electron) before expanding the process or IPC surface.
